# 背景、抠像与交付

## 生成背景优先级

用户另指定背景时按其要求。否则，**模型支持真实Alpha输出时，首轮优先生成透明背景**；使用对应透明参数，提示词写“透明背景，背景无场景、文字或额外物体；角色独立光照”。不能同时写纯白背景。未知能力先查工具实际参数/文档，不仅凭PNG或RGBA判断支持。

输出须实际含全透明空白和非空主体。忽略透明请求、返回全不透明Alpha或明确不支持时，记录实际情况，降级为白色RGB背景；接近均匀中性白即可，不因微小近白偏差反复返工。白底不影响角色本色、材料和独立摄影棚打光。

Alpha输入和输出能力分别判断：后续模型不接受Alpha输入时，临时合成白底RGB供其参考，放制作记录中；透明原件保留。此内部转换不改变交付背景版本，也不要求把透明输出整体改成白底。不可仅改文件扩展名。

## 非透明图片抠像

需要透明输出或白底矩形妨碍总览排版时，用已释放的 [网页编辑器](canvas-editor.md#背景处理) 在本机处理。优先测试其默认 BiRefNet-Full，轻量选项 BEN2，毛发细节可比较 RMBG-2.0；这三个模型默认（强度50、柔化0），以上模型都没下载选用 Shared Sampling（强度26、柔化1.5px）。模型复用本机缓存，方法选择与运行条件以网页参考为准，不为技能审查或普通交付自动下载模型。

已有有效Alpha默认保留。重新尝试始终从原始不透明源出发，不覆盖原图；处理结果保持原图尺寸，另存候选并保存输入、方法/参数和输出哈希，状态初始为 `not_evaluated`。批量处理也沿用上述四种方法；实际环境无法执行时记录限制。不能将估计Alpha冒充生成模型直接输出，也不能将下载完成或处理成功当作视觉通过。深浅底预览只用于检查，不作为另一套交付背景；单张失败独立记录，不编造成功。

一张白底合成图不能唯一反推发丝或薄纱的真实透明度和前景色。检查原生局部及缩小整体：主体内部是否漏底，细发丝/珠链是否丢失，轮廓是否白边/硬切/锯齿，薄纱是否被挖空、染白或失去叠层。只能验证实际效果，不能声称恢复了未知的原始Alpha。按实际用途区分轻微边缘瑕疵与主体损坏：用于白色总览、或用户已接受的轻微白边可以保留，不能仅因深底可见白边就退回白底原图或反复抠像；误删发尾/薄纱/饰件、内部漏底、明显残底、脏点或颜色损坏仍须处理。用户要求抠像试跑时，总览实际使用透明结果，原图拼贴不能代替成功抠像；确有主体损坏且无法保住时才说明试跑失败和白底回退原因，不把回退版标成抠像成功。

## 四视图总览

总览是四张当前图的本地排版，不再交给图像模型生成多视图。**固定2560×1440不透明白色画布，无标题、标签或文字描述；顺序为特写—正面—人物左侧面—背面。** 特写最高图层、最后叠放、紧贴左下角。默认裁去外围空白后的特写实际显示宽度**至少占画布三分之一，即不小于854像素**；空间宽裕可略大。不能靠增加透明/白色边框凑占比，也不能为了装下三视图把特写缩成小头像。用户明确另指定比例时才覆盖，记录其原话/要求。

右侧三视图等比缩放，**默认同高并共用上下基准，上下错位为0**，人物占比在可接受外缘交叠范围内尽可能大。能放进画布不是完成条件：先去外围空白、收紧横向间距，再搜索更大的三视图；同一三视图高度下再尽量增大特写。不要为小幅放大收益抬高或压低某一视图，也不能把示例尺寸、起始尺寸或可读性下限当作放大上限。**最右背面图的实际可见轮廓贴画布右边缘，默认右留白为0；图片透明空白框贴边不算主体贴边。** 完成放大检查后才把剩余横向空间分配到视图之间，不以拉开大间距代替放大。保留可辨认的脸、发丝和服装细节，不裁人物或拖尾、不拉伸身体、不反复生成角色来解决排版。原尺寸透明/白底单图保留，排版缩放只作用于总览，不靠锐化、噪点或伪高频掩盖缩小。

避让按**完整可见轮廓**判断，包括发髻、发尾、长饰件、珠链、手脚、袖子、薄纱、裙子的各层及拖尾。透明空白框可以交叉，也允许经实际局部检查确认的极小、低影响外缘交叠；不能为了追求零交叠无必要地压小人物。可见内容不能大片叠压，不能使关键发尾/裙摆、饰件或结构被盖住、层次丢失、两个视图粘连或轮廓难以区分；脸和手脚没被挡也不能据此通过。

```bash
python "<技能目录>/scripts/compose_review.py" preview "<本套目录>/制作记录/交付清单.json" --root "<本套目录>"
```

脚本用 `scripts/overview_layout.py` 计算可见Alpha轮廓逐行的间距，不同视图不强制等宽栏。默认 `maximize_subjects:true`：三视图从可用高度1430向下以10像素步长搜索，优先最大可行高度，再在该高度搜索最大的特写宽度；记录上限、下限、步长及更大候选被拒绝的数量。默认 `head_width:880/body_height:1200` 只是起始偏好，**不是放大上限**；特写最低可见宽度854、高度上限1440，三视图搜索下限960、底线1430。`layout` 可设置 `head_width/head_height/head_min_width/body_height/body_min_height/body_bottom/gap/max_vertical_offset`；默认 `max_vertical_offset:0` 保持上下对齐。只有用户允许错位时才显式设置非零值，最多60像素。

`edge_overlap_px:128` 是逐行间距搜索的横向范围，不表示允许遮挡128像素。算法先尝试不交叠，无法满足同一尺寸时再搜索微小外缘交叠；还分别检查各视图对的可用余量，避免某一对的限制不必要地压小整组。每对交叠面积不得超过较小可见主体的0.5%，且所有正交叠都产生待检查项，实际局部观察决定能否接受。面积虽小但遮住结构的候选仍不通过：保存失败观察，用 `edge_overlap_limits` 按视图对缩小搜索范围（例如 `{"head:front":20}`，0表示该对完全避让），然后重新搜索其余可用空间并重新看当前结果；不能只看面积通过。用户明确要求固定较小尺寸时可设 `maximize_subjects:false` 并记录 `fixed_scale_reason`；不能为省事自行关闭放大搜索。

透明图外围裁切与贴边均按Alpha大于4的可见轮廓计算，透明外围及抗锯齿极弱Alpha不计作主体；不能按含极弱残点的空白框对齐而让实际人物上下错位。白底RGB保持矩形避让和原RGB合成，贴边只检测与白底有差异的外缘，不伪造Alpha。背面仅不可见透明外围或空白背景可越过画布，可见像素不得被裁掉。默认 `right_margin:0`；用户明确要求右侧留白时填写其像素值和 `right_margin_reason`，不能为排版自行留白。`body_min_height` 是保持可读性的搜索下限，不表示达到该尺寸就天然清楚。特写上限必须容纳下限；仅用户另指定更小比例时填写 `head_min_width` 与 `head_min_width_reason`，不得用空间不足自行编造用户授权。旧 `overlap_px:0` 可保留，非零强制覆盖不再使用。`layout.subject_boxes` 可提供已实际查看的原图主体框，仅去外围空白；抠像脚本不由排版脚本暗中调用。

透明单图以真实Alpha参与合成；白底单图不会被排版脚本伪造成透明，只去外围空白并按矩形避让。来源、尺寸、等比倍率、裁切、位置、图层、放大搜索、可见主体交叠位置/面积和当前哈希均记录。自动几何搜索可生成待检查的微小交叠候选，不能代替视觉验收或自动批准。

实际打开**最终总览**检查特写占比、人物大小、上下对齐、留白、取景完整性及所有相邻视图。还须试探继续放大一个步长，确认更大候选因画布、特写下限或不可接受的交叠而失败；明显仍能放大就继续调整，不能以“图都放上去了”结束。放大检查靠近或交叠的发尾、衣料、裙摆和饰件，必要时将“原单图局部—总览同部位”制作成一张紧凑对照，确认没有因排版损失有效结构；观察另存，不往总览或对照塞解释文字。源图、尺寸或位置改变就重建、重看，不沿用旧判断。

`check_delivery.py` 重新读取源PNG，检查特写最低宽度、裁切/等比缩放、三视图同高及上下基准、完整可见轮廓交叠、背面实际右边距及被画布裁掉的可见像素，并按来源和位置重合成以核对实际总览；JPG总览先按相同质量99及4:4:4参数编码重合成画布，再核对实际编码与解码像素，不能把JPEG损耗当作几何变更。默认还独立重跑放大搜索；三视图或同高条件下的特写仍能放大至少一个10像素步长就拒绝，不能只信旁录写了“通过”。右侧仍留白、只把透明框贴边或以裁掉衣料/发尾消除留白均不通过。所有微小外缘正交叠须在旁录 `overlap_review` 中按 `head:front` 等实际视图对记录 `judgment:"minor_edges_only"`、具体 `observation`、`viewed:true`、当前 `preview_sha256`，以及真实局部对照的 `evidence_file/evidence_sha256`。脚本辅助上限为较小主体可见面积的0.5%，超过即拒绝；面积小也不能遮关键饰件、边界或服装结构，仍由模型看实际局部决定。脚本通过不等于人物设计或图片质量验收通过。

## 文件与最终发送

默认最终保存至用户素材目录的新交付子目录。先在工作区生成的结果须在最终回复前整套复制到素材目录并核对，不能仅交付工作区链接。用户明确另指定目的地才替换此默认值；写入受限按当前环境授权方式处理，未完成写入不得报告交付完成。当前四张的统一文件名及生成候选目录、编辑器索引，按 [候选归档与编辑器交付](candidate-delivery.md) 执行。每套保存头部特写、正面、左侧面、背面的当前版本及对应总览；每个视图**只交付一种背景版本**：有合格透明版就只交付透明PNG，否则只交付合格白底PNG。白底总览始终保留，是展示用途，不是为透明单图另交付白底副本。临时RGB参考、诊断背景、引导辅助图、独立部件和来源记录放 `制作记录/`；制作过程中的特写、正面、侧面、背面候选（含失败版）集中放工作目录的 `候选/`；交付时把完整PNG字节保存在 `网页资源/画布数据`，默认不另复制候选原图文件夹。按 [交付目录](candidate-delivery.md#交付目录) 将网页入口、当前四图、总览和角色描述放本套外层，运行文件放网页资源，全部候选与加载数据随套保存。

每套生成完成后必交付 `角色描述.md`，与当前四图同目录；包含名称、身高、年龄、外貌、该套服饰及材质。按 [描述规则](prompt-templates.md#角色描述) 只写角色设定，不含解释或备注。身高/年龄判断依据、选材、推断及验收信息放制作记录，不能混入该文档。保留被替换旧文档。

**最终回复只展示每套的四视图总览，不展示或逐一发送特写/三视图单图；同时提供本套网页或目录入口。** 总览默认以JPG质量99、4:4:4采样导出，文件名为 `角色名称_描述性造型后缀.jpg`，例如后缀“小熊套装”“泳装”“浅青花叶裙”；不能用“套装1/套装2/造型A”等编号替代内容。后缀从实际服饰概括，不随意添入无依据的身份或材质。

制作清单登记用户素材目录 `material_directory`；完整交付检查要求 `--root` 位于该素材目录的交付子目录中。仅用户明确要求其他目的地时，写 `delivery_directory_override_reason` 记录其要求；环境默认目录不能作为理由。工作区中间检查用 `--files-only`，不冒充已交付。每套填写 `description_file:"角色描述.md"`，完整检查将拦截缺失/空文档。用户明确不要描述时才可写 `require_description:false` 及 `description_omission_reason`。`background_mode` 为 `transparent` 或 `white`；少数视图能力不同可用 `background_modes` 按角色键记录实际版本，不为统一形式额外重生成。

```json
{
  "character_name":"角色名", "head_ratio":"3:4", "body_ratio":"9:16",
  "material_directory":"<用户素材目录的实际绝对路径>",
  "outfits":[{
    "name":"小熊套装", "folder":".", "background_mode":"transparent",
    "preview_file":"角色名_小熊套装.jpg",
    "description_file":"角色描述.md",
    "review_file":"制作记录/小熊套装_验收状态.json",
    "files":{"head":"01_特写.png","front":"02_正面.png",
             "back":"04_背面.png","left":"03_左侧面.png"}
  }]
}
```

```bash
python "<技能目录>/scripts/check_delivery.py" "<本套目录>/制作记录/交付清单.json" --root "<本套目录>"
```

完整模式检查实际交付目录、每套非空Markdown角色描述、四张当前PNG的路径、比例、背景分支、总览名称/尺寸/层序/贴边/源哈希、网页释放资源和候选索引，以及 [当前验收记录](stage-review.md)。缺少 `description_file` 时仍默认检查 `角色描述.md`，不能通过漏填字段跳过。`--files-only` 仅用于暂存文件检查，不批准整套。脚本只验证文件和记录，`model_visual_checks:false`；描述是否只含角色设定、三选一是否如实执行、视觉观察、Alpha边缘和实际重叠仍由执行者核实。
