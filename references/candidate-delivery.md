# 候选归档与网页交付

整套制作、返工后的整套交付和既有图片的编辑器打包使用此流程。单张试跑只归档本次图片与真实调用；用户另要网页时可以单独释放空编辑器，不强行生成其他视图。

## 交付目录

默认在用户素材目录新建交付父目录，按人物和描述性造型分套。工作区仅作制作/暂存位置；先在工作区完成时，最终回复前复制整套到素材目录，核对四图、总览、角色描述、全部候选及网页数据后完成交付。仅用户明确另指定目的地才改用其他位置，环境默认输出路径不算用户指定。每套是可整体搬移的独立目录：

```text
交付父目录/
└─ 角色名称_描述性造型/
   ├─ 01_特写.png
   ├─ 02_正面.png
   ├─ 03_左侧面.png
   ├─ 04_背面.png
   ├─ 角色描述.md                 本套角色设定，含身高和年龄
   ├─ 角色名称_描述性造型.png       2560×1440无字白底总览
   ├─ 编辑画布.html                 网页入口
   ├─ 使用说明.md
   ├─ 网页资源/
   │  ├─ 后端服务.cmd             前台终端启动器，关闭终端停止服务
   │  ├─ 交付索引.js               双击HTML使用的图片快照
   │  ├─ 画布清单.json             网页图片与候选账本
   │  └─ …                       本机服务与运行配置
   ├─ 候选/                       全部实际生成的四类视图
   └─ 制作记录/
      ├─ 角色名称_描述性造型.png.json  总览来源、位置与检查旁录
      ├─ 交付清单.json            制作与验收清单
      ├─ 图片选用文档.md
      ├─ 验收目标.json
      ├─ 验收状态.json
      ├─ 三选一记录.json           每视图三次调用与选择依据
      ├─ 调用记录/                实际提示词、有序输入、来源和哈希
      ├─ 引导/                    剪影、路线、独立部件等
      ├─ 对照/                    全图与局部验收证据
      ├─ 抠像/                    有需要才保存处理旁录和诊断图
      ├─ 画布数据/                供本地HTML惰性加载的图片脚本
      └─ 网页释放.json            已复制网页资源的版本与哈希
```

子目录按实际需要创建，不要求空目录占位。总览可以与四张当前图并列；文件检查只核对声明的四张和总览，候选、对照、引导不会被误算成当前成图。多套不共用当前图片或候选账本。已有用户目录按其要求保留，更新前保留被替换文件；用户要求整理目录或升级网页包时，按上述结构迁移辅助文件并备份旧入口，保留图片、描述及制作验收内容。

制作清单与网页账本用途不同：`交付清单.json` 用 `head/front/left/back`；`画布清单.json` 用 `head/front/side/back`，其中 `left → side`。不能将两种结构互相传给对方脚本。制作清单放在 `制作记录/` 时，两套Python命令均显式传 `--root <本套目录>`，清单里的来源、总览、验收路径相对本套目录。

## 候选和版本

- 当前四张由 [三选一](quality-and-revision.md#合格视图三选一) 后的实际验收记录确定，不自动选最新。所选图及另两张候选都保留并登记实际状态，失败历史也保留。合格透明版优先，否则合格白底版；每个视图只交付一个当前背景版本。
- 每次生成后立即归入该人物的 `候选/`，保留全部原生图片，包括未选中、未验收、失败及替代版。四类跨视图连续编号，如 `000001_特写.png`、`000002_正面.png`、`000003_背面.png`；不得覆盖重试，按视图和原生SHA-256去重。
- 调用时间或可靠调用账本提供顺序。历史无可靠时序用 `000000_背面_历史导入_<哈希8位>.png`，不编造顺序；新候选接续现有最大编号。
- 引导、部件、裁切、诊断图和对照也保留，放 `制作记录/`；它们不混成网页视图候选。原生文件按字节复制并核对哈希，抠像等处理版明确来源、方法与原生版本。
- 候选PNG、账本、索引及加载数据随整套交付，不只保留当前四张或内嵌缩略图，不因整理目录、重新打包或体积较大而删减历史图片。
- 网页选图、抠像、几何排版和导出不会自动批准候选。当前图字节变化时，保存处理结果与旁录，重新检查受影响项目、更新批准哈希、当前文件、总览和索引，再正式交付。

## 直接复制网页包

`assets/canvas-editor/` 是现成的可释放文件树，包含当前网页、入口、使用说明和 `网页资源/`；交付时复制这些文件，不现场重新编写HTML、从旧人物交付抽模板或把某个人物的内嵌图片留在通用模板。模型权重和原生运行库不在技能包中。

通常运行打包脚本即可一次完成图片归档、索引和网页释放；它只使用Node.js内置库，无需npm安装或联网：

```text
node <技能目录>/scripts/package_canvas.mjs <打包配置.json>
```

配置路径建议写实际绝对路径；相对源路径与 `output` 均按配置文件所在目录解析。`candidates` 按真实生成顺序排列，当前四张也必须在输入或已有账本中：

```json
{
  "character":"角色名称_描述性造型",
  "output":"<本套交付目录>",
  "current":{"head":"<合格特写.png>","front":"<合格正面.png>","side":"<合格左侧面.png>","back":"<合格背面.png>"},
  "candidates":[
    {"path":"<原生图.png>","view":"head","generatedAt":"<实际调用时间>","orderEvidence":"<真实调用条目>","statusLabel":"已验收","sha256":"<真实SHA-256>"}
  ]
}
```

`generatedAt` 或 `orderEvidence` 至少一项有可靠证据；没有时序的历史条目设置 `legacy:true`。处理版可加 `provenance` 记录原生来源和处理旁录。脚本先核对来源、已有候选和静态资源再写入；同名异内容候选拒绝覆盖。重新打包保持编号，备份被替换当前单图和已修改网页资源。

只给既有目录更新网页包，或用户单独要空编辑器时：

```text
node <技能目录>/scripts/release_canvas.mjs <本套目录>
```

此命令复制静态文件并记录释放哈希；升级旧交付时将索引和账本迁入网页资源、总览旁录迁入制作记录，并备份旧网页入口和启动器。保持图片、候选、索引内容和验收状态。图片或候选发生变化仍须重新打包，单独释放不能代替更新索引。

## 交付顺序与检查

1. 归档实际生成的候选；正常整套制作完成每视图三选一及必要抠像检查，确定当前合格四张，并写本套 `角色描述.md`。
2. 用打包配置复制四张、更新候选账本/本地图片索引，并直接释放技能内网页包。
3. 以同一套当前图制作总览、实际查看主体和相邻轮廓；网页自动排版仅作调整起点，不替代总览视觉验收。见 [总览规则](background-and-delivery.md#四视图总览)。
4. 核对制作/验收清单、当前哈希、角色描述和网页释放记录。先在工作区制作的整套，此时复制到素材目录，在最终目录运行交付检查并核对复制文件。新模板或打包脚本变更后，从新释放目录实际打开网页，检查四图加载、同类候选与启动器访问；普通交付复用已验证模板，检查本套数据即可，不重复下载模型。
5. 确认最终目录实际存在完整文件后，再回复展示总览，并给本套目录或 `编辑画布.html` 入口，使用户找到素材目录中的交付。四张单图无需逐一发送。单张试跑只报告实际范围和未验收状态。

```text
python <技能目录>/scripts/compose_review.py preview <本套目录>/制作记录/交付清单.json --root <本套目录>
python <技能目录>/scripts/check_delivery.py <本套目录>/制作记录/交付清单.json --root <本套目录>
```

正式整套交付默认同时检查网页入口、释放资源及图片索引。用户明确不要网页时在制作清单写 `require_editor:false` 并记录该范围；`--files-only` 仅作文件检查，不批准视觉结果。

网页操作、默认尺寸、JPG品质、模型和离线边界统一维护于 [网页编辑器](canvas-editor.md)，不要在不同流程重复追加界面规则。
