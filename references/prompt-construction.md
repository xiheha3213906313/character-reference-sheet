# 提示词构建与冻结

把图片分析得到的真实设计准确传入一次调用，而不是堆叠“严格一致”“高清”“不要出错”。适用于特写、三视图和受控编辑；不依赖某个角色、材料或模型。

## 把关键设计写成可观察约束

完整特征表服务选材、跨视图规划与验收，不等于每条都要展开成提示词。首轮以清楚、互补的真实图片提供身份与设计，文字写同一角色、参考用途、必要可见特征及呈现目标；没有歧义的细节可由图片承担。不能因为记录了某个ID，就要求其全部几何描述进入首轮。

以下详细约束用于图片不足以消除歧义、三视图的关键空间关系、用户明确要求或已经发生的具体失败。只挑本轮需要明确表达的事实，同一部件沿用稳定ID，关联真实输入与验收项；先回看源图，不依据候选补造原设计。

- 关键延伸部件：完整可见时写固定点、路径、相对身体/对象锚点的终点及宽厚/尺度；部分入画时只约束可见段的尺度、连接、路径与自然出画关系，不要求展示画外终点。完整结构仍留在特征记录中。单写“长”没有长度约束，不将不同裁切的像素数当作实际长度。
- 固定点指真实连接对象及位置，不等于被遮挡后首次看见的链/带位置。检查承载部件是否仍独立、每条链是否接回正确对象；数量/末端正确也不能放行根部合并。看不见的根部回查互补角度，仍无证据时按未知/采用方案记录，不能强造共用接点。
- 复合部件：写独立数量、每件主形、各自连接处及内外/前后关系。不能只写“双层”“多层”，让模型把独立对象合为一件新的装饰。
- 服装和图案：写实际裁片/叠层归属、搭接/收口与主纹样几何；独特主形的外缘分段、凹口、内部构件与相互关系须按清楚原图交代，不能只用相似物体名覆盖真实轮廓。微观材料与设计图案分开。清晰化不能授权换轮廓、数量、位置或结构。
- 完整部件辅助：在首次生成前准备本轮必要的完整设计，注明辅助图承担结构还是材料/色调；部件图光色不合本套时不锁定其配色与光照，由有效角色依据提供统一光色。避免在旧部件上叠新部件的冲突参考，保持同一实体及已确认数量。
- 可见性：区分完整画内、被真实物体遮挡、自然延续出画。画幅只切断可见范围，不改变部件；延伸件自然出画时不在画内提前收尾。按下述筛选决定哪些事实进入本轮提示词。

这些是适用项，不给所有普通褶皱或不可见微细节强制编号。模板中的关系须替换成真实源图事实；未知内容按既有推断规则处理，不能为“约束完整”猜造独特结构。

数量与长度的适用范围须逐件明确：成对或多股结构逐件写连接和可见路径，完整入画才写实际末端锚点。确认原图确有独立件才要求独立；同一结心的多组结瓣不能凭“双层”擅自改成两个结心。每条路径要能追到末端、遮挡处或自然出画，不能一条满足就算整组通过。不同投影不强制所有末端等高。

图片左右只用于本视图定位；需要跨视图追踪时，记录它与角色自身左右/真实所属位置的映射。同一物理部件转到背面或侧面仍沿用原ID，不能因屏幕位置改变就交换归属。

数量约束同时保留组件边界和原尺度，避免对象数量写对却扩满整个承载面。邻近独立部件补清相对位置和各自终端；长短差异明显且源图可比时，可用大致比例帮助区分，不能只反复写“独立”。对象自然投影/遮挡按证据解释，不能为显示编号搬动物体。

## 表面疑点进入实际调用

表面疑点按 [材质细节判别](surface-detail-diagnosis.md) 确认后，材料约束分别写恢复目标/有效依据、异常排除范围与设计保留项。实际输入同时纠正：污染区域不再承担材料用途，必要的图案或结构仅限定其有效部分。不能只追加“清楚、无噪点”，却继续传污染大图并要求保留全部纹理；也不能把未确定的斑块命名成织纹/刺绣来锁定。未受影响的真实随机质感、印花及有意做旧照常保留。

## 按目标画幅筛选内容

先确定视图、画幅范围和用户指定的构图优先级，再逐项判断完整入画、部分入画、遮挡或完全画外；不能把完整角色设定直接当成本轮视觉提示词。

- 完整入画：传入该部件必要的形状、材料、连接及空间关系。
- 部分入画：只写可见段及其连贯关系；需要时说明自然穿出画边，不命名或展开画外终点、相邻饰件和整件衣服。全部真实结构在特征记录中保留，后续视图重新选取。
- 完全画外且不影响可见投影：从身份、设计、输入用途及质量段中一并删除；也不写“可裁切/不用展示/允许出画”后继续列其具体设计。文本提及仍可能引导模型把它纳入镜头。
- 完全被遮挡：只保留确实决定画内连接、覆盖或轮廓的必要关系，不要求显示被遮挡设计。

实际输入同步筛选：删除只补画外内容的专用细节图；同角色整体图仍补充身份、头颈关系、连接或尺度时保留。不能因它也含画外服装就一律裁碎；只有无关人物/款式干扰、容量限制或确需更清楚局部时，再加原生裁切，保留必要整体上下文、全图来源和范围。不能裁掉关键连接或丢失更清楚的可见细节。只减少本轮输入，不删除素材或完整分析。

画幅决定自然可见范围，不授权预先规定所有长部件都截断。按实际长度、穿戴位置与本轮下缘判断末端是否入画；保留画内真实末端，不用“全部出画”替代长度分析，也不为展示画外末端扩大特写。

长马尾被左右边缘自然截断允许，不追加“全部头发完整入画”约束。特写胸口服装按原图实际高度选取可见段，不描述或强行展示下缘外的衣服，避免生成时把服装大幅提升到颈部；合理取景偏移无需增加精确测量词。

提交前逐项问“这段描述、这张专用参考是否会要求扩展本轮画幅？”：若只服务画外展示则删掉，而不是再添加更强的居中否定词。文本和输入同时改变时如实记录，不把结果变化全归因于措辞。

## 先解决构图冲突

身份/关键设计、必要空间关系、重要轮廓完整及 [指定呈现](presentation.md) 共同构成目标；用户明确要求优先。特写提示词仍写面部上下居中，实际验收依 [特写位置与占比](presentation.md#特写位置与占比) 接受合理偏移，不把精确居中列为硬门槛。头部姿态、镜头注视和中性表情分别落实；脸尽可能大的程度、次要服装展示量及合理画幅调整可以协调。

依 [画幅方案](presentation.md#将构图目标落实到画幅) 先定重要边界、面部目标位置及下缘身体范围，再定统一尺度/位置；这些目标共同可行，不能把重要头饰默认贴顶。禁止同时把脸最大化、眼线精确居中、完整领口和全部悬垂末端列为必须，却不检查是否能放进画幅。只写本轮必要的整体相机/画幅调整及部分可见部件的出画关系；不能让模型缩件或搬动服饰来解决冲突。

反复贴边时，将“适当边距”改为本任务可观察的缓冲区，例如最高重要轮廓上方明显留白，必要时给大致画幅比例或同原图标注。比例是本次构图辅助，不是通用像素门槛；不把细发丝和无关微差当重大失败。

## 单一实际提示词

按以下顺序由 [固定通用模板](prompt-templates.md#固定通用模板) 组装，只出现一份构图与一份呈现目标。所有通用内容从脚本模板取用，不复制整份分析与验收标准，不另拟提示词：

1. 视图/比例与本轮允许变化；头部任务不塞无作用的身高、历史版本和编辑次数。
2. 可行的构图硬条件及可协调目标；特写/正面的相机、头部姿态、注视目标分别明确；自然画外内容和整体调整方式。
3. 必要可见设计与确需说明的关键关系，关联真实输入；身份依据与设计依据不能互相代替。
4. 有序图片的限定用途、材料/本色/画风保留范围。
5. 指定光照、表情、背景与实际质量要求；编辑时加入规定的干净画面句。

不把选材报告、失败历史、哈希、源文件名、画外无关款式描述或多份旧模板塞进视觉提示词。保留本轮必要事实，删重复；精简不降低设计验收要求，也不设固定语言、字数或参考张数。分析中的五官尺寸可用于保真验收，不默认逐项重述成新脸；区分稳定身份与眼球转动、眼睑表情、嘴角牵拉等可变状态，不以“保留原五官关系”锁死源图的笑意或上视。

同一事实放在最适合的字段一次说清；复杂延伸件确需展开时，`statement` 写主形/数量，延伸字段写固定点/路径/末端/画外处理。不要在身份、输入用途、构图和质量段重复整套结构。输入用途说明来源分工，不抄全部约束，也不排斥同角色辅助图中的其他有效互补信息。表达仍长时先删重复；清楚图片能够承担的普通事实不必逐项转成文字，消除真实歧义的唯一关系不能删掉。

提交前实际核对：

- 本轮画内关键事实是否由实际输入覆盖，选定需文字强调的约束是否进入最终文本；不要求把完整特征表的每个ID展开，也不能以文字分工代替真实传图。
- 延伸件的真实长度、穿戴位置及可见性有无可靠依据；确需展开的约束是否完整，裁切是否被误写成缩短/缺失或统一强制出画。
- 只有一份光照、表情和构图目标；硬/可协调条件无冲突，固定内容与允许变化不矛盾。原图的笑意、头姿和视线不混入身份锁定；“闭嘴”“平视”“稳定视线”不能替代各自的实际目标。
- 身份/整体参考与细节裁切尺度是否有上下文；若孤立局部不能传递长度/位置，则补整体、连接上下文或简洁标注，不只重复“参考图片”。

对设计一致性敏感的任务，保留能显示关键关系的整体参考；精细脸裁切仅补身份，不替代整体穿戴关系。已有同角度有效原图时，可把它作为唯一编辑底图，辅助原始局部补画质；不要为更换背景/镜头无必要地全盘重设款式。参考容量有限时优先清晰互补图，排除被清晰图完整覆盖的相似模糊图；清晰度及覆盖由实际看图决定，不能按像素尺寸猜。必要参考都保留，由prepare自动去重及拼合直到装下：上下等宽、左右等高并保持比例，整图宽高比在9:16至4:3之间，不强制正方形，不删除独有材料/纹样。拼图的左/右/上/下或行列位置及各自用途自动写入提示词；正面原图材料区与剪影外形区保留各自限定，不共用一套服装设计答案。

文本仍反复漏数、提前收尾或合并部件时，使用同一原图的简洁标注副本辅助：逐件编号、沿真实路径标起止点，必要时加入同部件的原生小局部作计数定位。实际打开标注图确认指向真实对象；不凭错误候选画出所谓原设计。标注不得重画或变形源对象，放大仅作定位、不冒充更清楚的纹理。明确原图才是编辑底图，线、编号、定位栏只提供约束，不进入输出或转移其颜色。保存标注来源和实际输入，原生/整体对照仍要回看。

标注单独复查：线端是否真的指向所属固定点，还是仅指向可见段开头；是否跨到邻件、错误共用起点或连接原本分开的部件。被遮挡的连接不能用一条猜测线画成事实，只标确证的可见段并说明未显示部分。错误辅助图会把错误关系加重，不能因使用原图像素就默认标注正确。

构图验收默认沿用[呈现尺度](presentation.md)：头顶主体和重要头饰完整，飞丝触边允许；特写胸部及以上；左侧朝画面左且接近侧面。生成模板额外写略微拉远和最高重要轮廓上方留明显空白，避免贴顶；不把这个生成缓冲变成验收的固定边距门槛。源图头发模糊、面部脏污按固定质量句恢复有依据的清晰结构；具体污染区域或恢复证据填 `quality_notes`。

默认每阶段最多六次真实生图调用，包含追加、编辑和工具失败，跨配方累计。先修具体根因；达到上限由制作模型选优，不通过加严提示词反复追抽。

## 固定组装与真实调用

有Python时运行：

```bash
python -X utf8 "<技能目录>/scripts/build_prompt.py" "<提示词底稿.json>" --output "<本次提示词.txt>"
```

最小底稿字段如下；字段值来自实际任务，不把示例值当事实：

| 字段 | 记录要求 |
|---|---|
| `operation` / `stage` | `generate`或`edit`；`head/front/back/left`；默认比例、构图、姿态、呈现和质量由固定模板自动提供 |
| `references` | 有序非空列表；每项`image`和实际`role`，可选`kind`为`file`（默认）或`provider`；辅助图可用`guide`选择下述固定说明 |
| `identity` | 有依据的角色身份；不锁原图表情、光照或视线，不复制别的角色信息 |
| `critical_constraints` | 有序非空列表；每项含唯一`id`、`kind`、`source_indices`、`statement`。简洁首轮可用一条概括需保留的画内设计，不因字段存在而逐项展开全部特征 |
| 约束的`kind`与来源 | `shape/extent/layer/material/spatial`；来源为真实有序输入的1基序号，不能指向缺失图片 |
| 延伸件`extent` | `visibility`可选`complete`（默认）或`partial`；完整入画另需`attachment/path/end_anchor/frame_behavior`，部分入画只必需`path/frame_behavior`，连接或终点确实影响画内时才补对应字段；完全画外件不加入约束 |
| 可选 `allowed_changes` / `quality_notes` | 本次角色特有的允许调整列表、具体污染恢复目标；追加到通用模板，不能用来重写构图、呈现或通用质量 |
| 可选 `user_overrides` | 仅用户明确要求覆盖时填写。允许键`aspect_ratio/framing_required/framing_preferred/lighting/expression/background`，每项严格为`{"value":"实际目标","user_quote":"用户原话"}`；替换对应默认项，不叠加旧目标 |
| 可选 `background_mode` | 默认`transparent`；能力受限用`white`时须写非空`background_fallback_reason`；用户另指定背景走带原话的覆盖 |
| 可选 `corrections` / 参考的`guide` | 常见上视修复为`["gaze_up"]`，只用于特写/正面；guide支持`front_material/back_silhouette/rear_design/structure_silhouette/rear_layers/edit_annotation`，必须关联实际传入的对应辅助图 |
| `edit`追加字段 | `baseline_reference`为1基底图序号，`edit_target`为本次实际目标 |

可选`character_name/outfit/height_cm`仅记录必要信息；头部任务不将身高渲染入提示词。本地参考相对路径按**底稿目录**解析，缺失、非文件、空文件或不可读会在保存前报错；脚本验证文件字节，不代替打开图像。非文件型工具句柄须显式用`kind: provider`，调用者先用相应工具确认可用，脚本不能验证服务端资源，不能用它绕过本地文件检查。

最小底稿只填写变量；下例是假数据结构，需换为实际文件与事实：

```json
{"operation":"generate","stage":"head",
 "identity":"实际角色身份，不含原场景光或原表情锁定",
 "references":[{"image":"实际原图.png","role":"实际身份和画内设计依据"}],
 "critical_constraints":[{"id":"visible_design","kind":"shape","source_indices":[1],"statement":"实际画内造型"}]}
```

不再接收自由填写的`framing/presentation/quality/aspect_ratio`顶层字段。脚本保持变量与输入顺序，输出UTF-8提示词及旁录，含`template_id/template_sha256`和实际用户覆盖。调用读取完整输出与旁录有序`references[].image`，不再自由改写、追加通用段落或偷换参考。`--output`相对路径按运行目录处理；无Python时人工从同一模板取值并保存，不另拟通用文本。

修复时修改底稿中明确有问题的字段，保留其他已确证事实，重新组装并记录差异；上视问题用 [具体注视修正](presentation.md#镜头头部姿态与视线)，不只降低头部。不能在旧文本结尾不断堆“必须”“绝对”或另加一套目标，也不能为了过审改造型。安全拒绝只按既有实际拦截流程处理。

脚本只固定组装、查字段和保存版本，不理解空间语义，也不保证图像模型服从。稳定性须用真实结果检验：一次测试尽量固定其余输入/工具，只改所诊断的提示词；如需改变输入，单独记录原因，不能把混合改动的改善全归因于文字。检查关键目标和身份、设计、质量是否回归，失败先改具体根因，记录已有次数；不按调用次数自动宣布“模型能力问题”。
